# L00 · 下载仓库后，怎样验证自己真的能运行？

目标：区分“装了包”“选了内核”“数据路径正确”“模型能前向”。前置：会启动终端、认识 Python 变量。演示：`00_environment_check.ipynb`，定位 `environment`、`dataset`、`forward` 三个稳定 cell ID。状态：讲稿就绪，运行输出待验证。

## 开场与节奏（15 分钟）

- 0:00–1:30：展示 `ModuleNotFoundError` 与正确内核。开场：“同一台电脑可以有三个 Python。我们先确认究竟是谁在执行代码。”

- 13:00–15:00：演示包入口、缺失文件报错与课后任务。

## 六页幻灯片提纲

## 手算与代码

batch=2、16 类，logits 有 32 个数；argmax 后形状 `(2,)`，不是 32 个类别。对应 `PatchClassifier.forward`。现场只运行小 batch，不安装 GPU 驱动、不执行长训练。

## 课后改动与答案

把 batch 从 2 改成 3，输出应为 `(3,16)`；把类别数改成 9，参数和输出头变化但空间输入不变。未训练 logits 不应被描述为有意义的分类结果。

## 排错与备用

先打印 `sys.executable`，再查根目录与文件存在性；别反复装包。无 checkpoint 就显示重建命令，不能偷偷开始训练。备用为已嵌入输出，口播“这是预先执行记录”。

环境版本/数据形状报告是复现记录的第一页，不是模型性能报告。来源：Python `sys`、PyTorch tensor/module、Jupyter kernels 文档。AI 给出的安装命令必须与当前解释器核对；不复制不明下载链接。
